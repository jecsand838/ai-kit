# app-sdk Research

## Authority

Read the root and app `AGENTS.md`,
[`app-sdk/specs/SPECIFICATIONS.md`](../../../app-sdk/specs/SPECIFICATIONS.md),
the focused owning specs, and
[`agent-sdk/specs/API.md`](../../../agent-sdk/specs/API.md). The app
specification ledger is the sole exact public inventory. Lower crate-root
contracts define available composition. The approved fixed rurr pin resolves
overlapping core observable semantics under
[`workflows/RESEARCH.md`](../../../app-sdk/specs/workflows/RESEARCH.md). App specs
own exact public signatures, App-specific translations and explicit exclusions;
current external graph-engine sources remain comparative evidence only.

Use this skill for app workflow parsing, graph validation, deterministic
execution, checkpoints, recovery, retention, interactions, and lower-crate
composition. Route facts owned entirely by another crate through that crate's
research skill.

## Workflow

1. State the research question, decision boundary, and owning app specs.
2. Establish authority before inspecting evidence. Apply the approved fixed
   pin to overlapping core semantics and App specs to signatures, translations
   and exclusions. Lower crate-root ledgers define legal composition. Neither
   the pin nor current web sources authorize unplanned public vocabulary,
   native persistence records or lower-boundary expansion.
3. Separate normative contract, current implementation, test evidence, and a
   proposed change. Never infer production proof from specifications or static
   contracts.
4. Collect all three evidence tracks:
   - ai-kit app and public lower-crate contracts;
   - the checksum-verified fixed rurr ZIP;
   - currently verified official graph and workflow sources.
5. Label every finding as `Normative app rule`,
   `Normative lower-crate contract`, `Repository observation`,
   `Pinned rurr observation`, `Verified external fact`,
   `App-native inference`, or `Unresolved gap`. Attach a precise local path or
   web citation.
6. Compare execution semantics, graph validation, state/checkpoint behavior,
   failure handling, concurrency, and lifecycle without copying another
   framework's API or persistence model.
7. Route each responsibility to `app-sdk`, `agent-sdk`, `provider-sdk`,
   `tool-sdk`, `storage-sdk`, or the caller. Reject private-module access,
   opaque-value inspection, and duplicated lower-crate behavior.
8. Resolve overlapping semantic conflicts using the already-approved authority
   order. Record any remaining contradiction or expansion as an unresolved gap
   and require a separate app-sdk specification amendment before production.
   Applying an already-adopted pinned semantic does not require renewed approval.
9. Report scope, sources, classified findings, ownership, portability, proof
   limits, contradictions, and concrete impact on specs, code, tests, docs, and
   validation.

## Output Rules

- Distinguish sourced facts from inference and proposals.
- Preserve app-native vocabulary and crate-root public composition.
- Cite exact archive members and official web pages; record web version or
  document channel and access date.
- Preserve the adopted pin's core semantic authority without importing its
  public API or native records. Newer rurr/external versions cannot replace
  the fixed oracle or authorize unplanned capability.
- Do not describe static checks as runtime, durability, recovery, performance,
  or strict-live proof.
