# app-kit completion acceptance matrix

Planning supplement, 2026-09-13. Every row maps the prior 31-area audit to an executable acceptance condition. This is a plan, not evidence that these tests currently exist or pass. Current source anchors are edit locations, not immutable topology assertions. The main plan owns final names/signatures; rename target families here consistently if its consolidation chooses fewer test targets.

## Acceptance protocol

Each adopted row is complete only after (1) its behavioral/compile tests are added or changed first and fail for the intended missing behavior, (2) implementation makes them pass without weakening assertions, (3) independent subagent review checks semantics, ownership, reductions and test quality, (4) all substantive review findings are resolved, and (5) the phase's documented gates pass. Record the test case names, commands/results, source revision, review agent and disposition beside the row in the execution report. Source presence, schema prose and a passing aggregate smoke test are insufficient.

The pinned rurr baseline is `app-kit/vendor/rurr-main.zip`, commit `005bfe3ece631e64b06dac2d42ef84235f727a4f`, SHA-256 `5b5f20eb1d233467c600dc9dd249feaaa9046c5a303ae4e937040be5b6ecf25e`. The prior audit verified that checksum; the implementation run must verify it again before oracle execution. `rurr-main/...` references below are ZIP members, not files to edit in place. Never write to repository `tmp/**`.

Classifications:

- **Core**: fully implemented framework behavior is required.
- **Core + App extension**: rurr-mapped serial outcomes and App's explicit parallel/durable extension both need tests; an extension does not excuse a mapped difference.
- **Trait-owned integration**: behavior is furnished through existing public lower traits or caller-provided portable callbacks, not copied adapters or required supplied implementations.
- **Rust surface translation**: spelling, macros, aliases, wrapper names or persisted native encodings may differ, while accepted observable behavior remains. A semantic omission cannot be reclassified as a translation.
- **User exclusion**: tracking server/UI and its admin/annotation/indexing API, CLI, exporter product/observability-sdk, and provider/tool/agent/database adapter products belong outside app-kit. The user did not exclude core callbacks, state typing/codecs, lazy streams, local futures, checkpoint history or child execution controls.

## Callable binding, graph metadata and execution-mode proof

These concrete cases refine A03/A06/A11/A20/A22/A24/A26; they add no second
public contract or new product scope.

- `callable_definition_contract::callable_references_require_explicit_exact_revisions`
  first parses a valid control, then rejects missing, null, empty and malformed
  Action/custom Condition revisions. Required exact references are an explicit
  App deployment extension, with no latest/order selection or unique-key shorthand.
- `missing_or_duplicate_callable_pairs_reject_before_app_publication` covers
  absent key/revision pairs and duplicate inventory pairs, with zero App records,
  hooks, Action construction and predicate evaluation. Distinct revisions coexist.
- `custom_condition_revision_controls_state_only_routes_independent_of_inventory_order`
  proves exact c1/c2 behavior through opposite true/false routing, under both
  inventory orders, without depending on Action execution. The staged parser
  target authors current v1 solely to reach new grammar before the coordinated
